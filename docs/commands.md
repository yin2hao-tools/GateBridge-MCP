# 指令与权限说明

## 指令入口

主指令为 `闸门`，别名为 `gate`。它接受一个可选参数：操作名称，默认值为“帮助”。

| 操作 | 允许的参数 | 是否发送控制命令 |
| --- | --- | --- |
| 开门 | `开门`、`open` | 发送 `angle=180` |
| 关门 | `关门`、`close` | 发送 `angle=0` |
| 状态 | `状态`、`status` | 不发送板端命令，只读取最近报告 |
| 帮助 | `帮助`、`help` 或省略 | 不连接或控制设备 |

英文参数不区分大小写。插件不接受任意角度、任意设备 ID、临时令牌或上游地址参数。

## 授权规则

指令首先从 AstrBot 事件读取平台实例 ID 和真实消息发送者 ID，组成 `平台实例ID:用户ID`。插件不从昵称、消息正文、引用消息或群管理员角色推断身份。

以下任一条件成立时允许执行：

1. 配置开启继承 AstrBot 管理员，且 `event.is_admin()` 为真。
2. 完整授权标识在 `permissions.admin_ids` 中。
3. 完整授权标识在 `permissions.member_ids` 中。

缺少有效身份或无法匹配时，拒绝执行。名单不是列表时不会授予该名单的权限。字符串只做精确匹配，首尾空白会去除，不解释通配符。授权检查在连接配置读取和控制调用之前完成。

拒绝示例：

```text
你没有闸门控制权限，请联系管理员在插件配置页添加授权。
你的授权标识：qq_main:12345678
```

管理员在插件配置页把该标识加入名单。此回复不包含设备 ID、地址、状态或认证令牌。未授权指令不会发送开关命令。

插件管理员与指定成员拥有相同的开关、状态和帮助指令权限。插件管理员身份不会自动赋予 AstrBot 管理权限，也不能通过聊天修改名单。名单由拥有 AstrBot WebUI 管理权限的人维护。

## 开门与关门

开门向原后端发送：

```json
{"device_id":"mg946r-001","cmd":"angle","value":180}
```

关门将 `value` 改为 `0`。设备 ID 来自插件菜单配置。

只有收到原后端的 `success=true`、`queued=true`、`cmd=angle` 回执，插件才回复：

```text
开门指令（180°）已由原服务端转发，闸门是否到位尚未确认。
```

回执只确认原后端转发成功。当前协议没有可靠的机械到位确认；插件不会把目标角度写成实际角度。

## 状态

状态回复包含设备 ID、后端认证连接、设备在线情况、报告角度、报告位置、报告来源和距接收报告经过的秒数。

- 后端已认证，只说明插件已连接原服务，不代表 ESP32 在线。
- 原后端首次发送的快照可能是历史缓存，因此报告位置始终为未知。
- 后续广播超过有效期、上游断线或没有报告时，状态按未知或过期显示。
- 有效广播角度为 0 时显示“报告为关门”，180 时显示“报告为开门”；这仍不是实际到位确认。
- 心跳不包含角度时，角度显示未知，不会借用旧角度作为新报告。
- 第一次连接尚未完成时，可稍后再次查询。查询状态不会移动舵机。

报告接收时间不等于设备采样时间。原协议没有快照来源标识，极端并发断线时缓存和广播可能交错，无法严格识别每条报告的来源。

## 失败处理

| 情况 | 插件行为 |
| --- | --- |
| 连接配置缺失或无效 | 提醒检查插件菜单，不回显令牌或原始配置 |
| 原服务暂时不可达 | 后台自动重连；等待连接超时的本次指令不发送 |
| 认证失败 | 提醒检查设备 ID 和原后端令牌 |
| 原后端响应不兼容 | 提醒确认使用独立舵机接口 |
| ESP32 离线 | 返回离线提示，不排队重放开关动作 |
| 原服务拒绝命令 | 返回拒绝提示 |
| 发送期间断线或回执超时 | 提示指令可能已发送，需要现场核实；不自动重试或反向补偿 |
| 插件停用或重载 | 关闭连接，终止等待；已经发出的硬件动作不能撤销 |

## 连接与并发

插件固定以 `role=controller` 认证，不以 `device` 身份替换板子连接。首条认证消息包含设备 ID 和令牌，后续控制消息不重复携带令牌。

同一插件实例串行处理控制命令。回执超时后关闭旧连接，避免迟到回执被下一条指令使用。断线后自动重连和认证，控制命令永不自动重放。

原网页、原 Agent 和其他控制器仍可同时连接原后端。本插件的权限只约束本插件入口，不能限制其他入口，也不能建立全局控制互斥。
